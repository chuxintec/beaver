# Unified diagnostics

`beaver.diagnostics.summarize(inputs, output=None, max_items=100)` accepts an explicit array of JSON result/journal/process/UI inspection or wiring files and text logs. It reads and hashes the supplied files, never edits them, and returns `beaver-diagnostics/1` with a bounded list of diagnostics and evidence identities. With `output`, it creates a new directory and writes `diagnostics.json` inside it; the return value contains both that path and the report. Existing output paths are rejected.

Observed compiler formats include `file.cs(12,3): error CS1002: ...` and `error CS1002: ...`; stack traces with `in file.cs:line 12` preserve their source location. Warning severity does not become a failure. Structured UI `issues` are mapped once and preserve asset, node, field and certainty. High certainty alone does not imply failure; only explicit failure classification/status or error severity does. UI wiring `bindings` preserve blocked state and target location. Unity import, Editor attach, compile, Play, Player timeout and explicit entitlement/environment log observations are bounded; they do not establish a deeper cause. Unrecognized evidence remains `unknown`.

Execution facts (`executed`, exit code, actual changes, not-applied items, checkpoint) are copied from explicit fields. A schema rejection is post-execution only when execution is explicitly true; otherwise it remains `execution_unknown`. Cross-file joins require a shared explicit operation identity or a provider stdout artifact path and hash that exactly match another supplied input. A `writeSet` is never treated as applied output. Input SHA-256/path, JSON pointer or log line, and duplicate occurrences preserve evidence provenance. Counts report total unique diagnostics and truncation. Credential-like values are redacted in message text and sensitive-key values. Original input files remain the caller's evidence.

The module does not infer assembly, node, field, responsibility, or target from a bare keyword. Missing ownership/action details remain `unknown` with a request to inspect the evidence and identify the owner. This is a parser/aggregator, not an Editor controller, gameplay validator, or autonomous repair system. CLI wiring is provided by the version integrator as `beaver diagnostics summarize --input PATH ... --out NEW_DIR --limit N`.
